# 计划书写作规则

本目录是中文金融人工智能大赛项目计划书，不是英文期刊论文。用户要求写作者让Codex按名称下载并使用 `nature-writing` 和 `anti-defensive-writing`，不需要技能安装脚本、技能副本或安装证明。

## 范围与交付

- 只有吕洪宇（`hongyulyu714-prog`）和武桐宇（`Eazin-stefan3199`）撰写本计划书。不要因此更改仓库原五人研发团队或抹去其他人的贡献。
- 依照 `page-plan.json` 和本人Issue修改所分配的 `pages/`、个人图表、文献、证据账本和自检文件。共享模板变化另行协调。
- 按 `README.md` 提交正文、图表、证据、完整PDF与自检，必须通过PR交付；不要直接推送 `main`。
- 这是纯文档任务，不顺带重构后端、前端或现有业务数据。

## 内容与语言

- 先用一句话写清本节要说明的贡献，再安排支持它的材料；按问题、方法、证据和应用价值组织，不写开发流水账。
- 模块要交代为什么需要、怎样运行、如何验证；重要效果结论说明数据集、指标、对照、条件和来源。
- 保持中文自然直接。删去无实质信息的口号与AI套话；不为了显得谦虚而反复自我否定。
- 所有主张以材料为边界。不编造测试提升、用户访谈、合作客户、收入、市场份额、参考文献或已接入的大模型能力。必要风险和真实边界如实说明。
- 影响强度与方向分开；财务重要性代理不是健康度，影响分不是收益预测。模拟演示、独立数据包、正式业务集成分别表述。
- `nature-writing` 的英文输出默认不适用于本任务，按用户要求用中文；商业与团队章节采用适合比赛的结构。

## 图表与引用

- 真实截图注明提交/版本与模式，TEST合成图和Mock样例不能当真实业务效果。
- 图片文件名和引用键按作者前缀区分。表题在表上、图题在图下，表格使用booktabs，无竖线。
- 原始来源、日期、位置、口径和状态写入个人证据账本。只引用实际读过的来源，不上传Wind受限数据、凭据或受限全文。
- 使用 `main.tex` 编译完整文档；终稿约50页，以内容和可读性为先，不通过空白页和极小字号凑篇幅。
