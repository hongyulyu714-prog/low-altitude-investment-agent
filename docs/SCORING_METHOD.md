# 公司影响评分 V1

对应 Issue #3。版本 `impact-v1.0.0`。这是可解释的情景筛选规则，不是股价预测、投资建议或经过历史拟合的因果模型。

## 状态与数据来源

正式公司映射尚未交付。`data/company_universe.provisional.json` 固定20家临时样本及五组各4家的研究分组，暴露度一律为null、状态pending_verification。分组不代表公司全部营收来自低空经济；海特属于航空配套服务，中科星图属于数字应用服务，不能等同纯飞行运营商。

`data/financials.example.csv`、`data/scoring_companies.example.json`和`data/company_impact.example.json`全部是**人工公式生成的模拟数值**。公司代码/名称仅用于接口联调，财务数值、暴露度和排名都不是这些公司的事实。每行保留mock与来源占位URL `https://example.invalid/synthetic-wind-v1`（不是可核验业务证据）。生成器不读取任何用户私有导出。

用户提供的真实财务及日行情已在私有环境做内部一致性检查，但未逐项对照数据库与公告，绝不随PR提交。不得把内部自洽等同来源已核验。

## 三个分项

### Exposure：业务暴露度

正式输入由映射负责人提供0–100分，建议优先使用有年报依据的相关业务收入占比×100。若采用产品匹配度代理，须注明方法与证据，不能冒充收入占比。仅接受verified并有source_url的真实映射；未交付、待核验、缺证据返回null。模拟模式采用40、45、50、55循环，纯粹用于复现，并非对实际公司打分。

### Sensitivity：事件传导敏感性

采用事件与产业环节的0–100规则分。无量化冲击幅度信息，当前不推算利润变动。默认表只在明确allow_mock且映射为mock时启用。

| 情景 | 材料/动力 | 电子/控制 | 整机 | 基础设施 | 运营应用 |
|---|---:|---:|---:|---:|---:|
| 政策支持 | 55 | 60 | 85 | 90 | 80 |
| 关键原材料涨价 | 80 | 35 | 90 | 20 | 30 |
| 适航认证进展 | 35 | 50 | 95 | 45 | 85 |

政策支持强调基础设施和整机，适航进展强调整机与运营，原材料涨价强调整机成本。该顺序仅为演示假设，未经过实证校准。原材料涨价对材料/动力组方向标为uncertain（组内生产商与采购方可能相反），其他组示意negative；另外两类示意positive。特定认证只影响具体产品及其路径，正式应用不能把全行业都当作直接受益者。

正式事件规则通过每家公司`event_rules[event_id]`传入，包含`sensitivity,impact_direction,source_url,verification_status=verified`。缺规则返回null；不能默用模拟系数生成真实排名。证据的真实性仍需人工审核，程序只校验输入状态及来源存在。

### FinancialMateriality：财务放大程度代理

取统一2025年度合并财务；该分数刻画利润、现金流缓冲及杠杆带来的敏感程度，**不是财务健康度，也不是预计损益金额**。分数越高不代表公司越优质。

定义clip(x)=min(100,max(0,x))，毛利率和负债率均输入百分数（20而非0.20）：

- 利润缓冲压力 P = clip(100 − 2×毛利率)。毛利率0%映射100，50%映射0。
- 现金流压力 C = clip(50 − 250×经营现金流/营业收入)。现金流收入比−20%映射100，0映射50，20%映射0。
- 杠杆 L = clip(资产负债率)。超界保留异常标记。
- F = 0.40×P + 0.35×C + 0.25×L。

权重是V1设计选择：利润缓冲和现金流合计75%，杠杆25%；并非统计估计结果。参数与权重写入代码，修改须更新公式版本和样例。统一财务代理有跨行业局限，正式研究需评估行业可比性。

### 总分与方向

`Impact = Exposure × Sensitivity × FinancialMateriality / 10000`，各分项和总分0–100。分项F保留6位，总分保留2位小数。例：E=80、S=50、F=40，则总分16。影响方向独立保存，不把利空误写成负分；uncertain不等于零影响。

按影响强度降序排序，同分以证券代码排序；分数缺失排末尾、rank=null，不填0。零暴露度为已知零，应区别于暴露度未知。

## 缺失、异常与边界

- 必需财务字段缺失、营收≤0、映射未核验、事件规则缺失：总分null并返回missing_reason。
- NaN、无穷、布尔值、越界分项明确报错，不静默修正。
- 负毛利、负经营现金流保留风险标签；财务组件可截断，但原值不覆盖。
- PE/PB/PS和收益率、波动率用于上下文披露，不进入F。负PE不是便宜，高PE不直接造成高影响分。
- 研发/存货/应收/资本开支保留用于财务解释，V1不把每个可得指标都强行纳入权重。
- 中直股份历史重述、顺丰A/H市值口径仍需原始证据核验；截图中的AI解释只作待核验线索。
- 无公告日期时不宣称具备历史时点可得性，不能直接用于无前视偏差的回测。

## 运行与复现

```bash
python -m backend.generate_scoring_examples
python -m backend.scoring --allow-mock --output data/private/company_impact.json
python -m unittest discover -s tests -v
```

默认输出为被git忽略的data/private；不加allow-mock会拒绝模拟输入。240条样例包含60条年度、160条季度、20条同日市场记录，生成三类事件各20家公司排序，共60条。

接入现有总控：`to_financial_score(result)`返回既有FinancialScore字段，完整可计算结果可供总控读取。未知结果不能导出到当前只接收数值的旧契约，会明确报错，应由上游保留“资料不足”供前端显示。本PR不扩大既有HTTP契约。总控复核公式共用backend.scoring，避免计算漂移。

## 验收与敏感性验证

测试覆盖手算分数、0与null区别、缺失字段、非法数值、未核验映射、规则替换、现金流恶化导致压力分上升、暴露度减半、三情景排名可复算、20家公司/三年/八季/同日覆盖、重复与单位错误、样例重新生成逐字节一致、旧FinancialScore契约适配；并运行既有总控/API回归测试。

正式映射到位后，替换临时分组和暴露度，加入产品特定事件规则及证据，使用授权私有财务重跑。当前PR交付可复算V1和mock验收，不宣称真实公司影响排名已核验。
